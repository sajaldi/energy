Flujo Power Automate: Autorización de Solicitud de Materiales

Versión simplificada — El correo llega ya armado desde el sistema (campo email_html)

Origen: /inventarios/crear-solicitud/ Webhook: POWERAUTOMATE_APROBACION_URL Evento: solicitud_material_created
🔎 Cómo funciona (resumen)

El sistema (Django) hace un POST al trigger HTTP de este flujo. En el JSON, cada aprobador ya trae su correo completo listo en el campo email_html, con su nombre y sus botones personalizados de Autorizar/Rechazar.

Por eso el flujo es mínimo: solo recorre los aprobadores y envía a cada uno su correo. No hay que armar tablas ni pegar HTML.

Cualquiera de los aprobadores puede autorizar; el primero que lo haga cierra la solicitud. El correo incluye un indicador de estado en vivo que muestra si alguien ya aprobó.
1 Crear el flujo y el trigger HTTP
  1. Crea un flujo instantáneo (automatizado en la nube) en blanco.
  2. Primer paso: “When a HTTP request is received” (Solicitud / Request).
  3. Método: POST.
  4. Clic en “Use sample payload to generate schema” y pega el JSON de muestra de abajo. Power Automate genera el esquema.
  5. Guarda el flujo: se genera la URL HTTP POST. Esa URL ya está registrada en el sistema como POWERAUTOMATE_APROBACION_URL.

Sample payload (pegar para generar el esquema):

{
  "event": "solicitud_material_created",
  "solicitud_id": 123,
  "estado": "PENDIENTE_AUTORIZACION",
  "usuario_nombre": "Saúl Alvarado",
  "usuario_email": "saul.alvarado@ccg.hn",
  "aprobadores": [
    {
      "user_id": 5,
      "nombre": "Ricardo Zerrate",
      "email": "ricardo.zerrate@ccg.hn",
      "departamento": "Mantenimiento",
      "url_aprobar": "https://softcom.ccg.hn/inventarios/api/solicitudes/123/autorizar/?accion=aprobar&aprobador=5",
      "url_rechazar": "https://softcom.ccg.hn/inventarios/api/solicitudes/123/autorizar/?accion=rechazar&aprobador=5",
      "email_html": "<table>...correo completo ya armado para Ricardo...</table>"
    }
  ],
  "aprobadores_emails": ["ricardo.zerrate@ccg.hn"],
  "url_detalle": "https://softcom.ccg.hn/inventarios/mobile/pedidos/123/",
  "url_estado_badge": "https://softcom.ccg.hn/inventarios/solicitud/123/estado-badge.png"
}
2 (Opcional) Condición por estado

Si solo quieres enviar correo cuando la solicitud requiere autorización, agrega una acción Condición:

  • triggerBody()?['estado'] es igual a PENDIENTE_AUTORIZACION
  • Pon las siguientes acciones en la rama “En caso afirmativo”.
Si no agregas la condición, el correo se enviará siempre que llegue el webhook.
3 Recorrer los aprobadores
  1. Agrega la acción “Aplicar a cada uno” (Apply to each).
  2. En “Seleccione una salida…” pon: triggerBody()?['aprobadores']
Este bucle enviará un correo por cada aprobador del departamento. Cada uno recibe su propio enlace, para poder saber quién autorizó.
4 Enviar el correo (dentro del bucle)
  1. Dentro del “Aplicar a cada uno”, agrega “Enviar un correo electrónico (V2)” (Office 365 Outlook).
  2. Configura los campos:
CampoValor
Para@{items('Apply_to_each')?['email']}
AsuntoAutorización requerida · Solicitud #@{triggerBody()?['solicitud_id']} · @{triggerBody()?['usuario_nombre']}
CuerpoCambia el editor a modo código </> y coloca: @{items('Apply_to_each')?['email_html']}
Eso es todo el correo. El HTML ya viene relleno con el nombre del aprobador, la tabla de materiales, el badge de estado y sus botones Autorizar/Rechazar.
El nombre Apply_to_each debe coincidir con el de tu acción real (Power Automate reemplaza espacios por guiones bajos). Si tu bucle tiene otro nombre, ajusta las expresiones.
5 Responder al sistema (recomendado)
  • Después del bucle, agrega una acción “Response” con código 200.
  • El sistema espera respuesta en menos de 10 segundos (timeout del webhook). Mantén el flujo ágil.
🖼️ Estado en vivo dentro del correo

El correo incluye una imagen (url_estado_badge) que muestra el estado actual: Pendiente de autorización, Autorizada por {nombre} el {fecha} o Rechazada por {nombre}. Se actualiza cada vez que se abre el correo.

Algunos clientes (Outlook) bloquean imágenes remotas hasta que el usuario las habilita. Si no se ve la imagen, al hacer clic en un botón la página de confirmación igual indica si la solicitud ya fue resuelta.
✅ Botones Autorizar / Rechazar

Ya están incluidos en el email_html de cada aprobador y apuntan a:

  • .../inventarios/api/solicitudes/<id>/autorizar/?accion=aprobar&aprobador=<user_id>
  • .../inventarios/api/solicitudes/<id>/autorizar/?accion=rechazar&aprobador=<user_id>

Al hacer clic, el sistema registra quién autorizó/rechazó y muestra una página de confirmación. Si otro aprobador ya lo hizo antes, mostrará “Ya {nombre} autorizó esta solicitud”.

🧪 Prueba de punta a punta
  1. Guarda y activa el flujo.
  2. Crea una solicitud en /inventarios/crear-solicitud/ con materiales de un departamento que tenga aprobadores configurados, y pulsa Enviar Solicitud.
  3. Revisa el historial de ejecuciones del flujo: debe registrar la llamada entrante.
  4. Verifica que cada aprobador reciba su correo con la tabla de materiales y los botones.
  5. Haz clic en Autorizar desde un correo → debe mostrar la confirmación. Abre otro de los correos → el badge/página debe indicar que ya fue autorizada.
🧰 Estructura final del flujo
When a HTTP request is received  (POST)
└─ (opcional) Condición: estado == PENDIENTE_AUTORIZACION
   └─ Aplicar a cada uno: triggerBody()?['aprobadores']
      └─ Enviar un correo electrónico (V2)
             Para:    items('Apply_to_each')?['email']
             Asunto:  Autorización requerida · Solicitud #... 
             Cuerpo:  items('Apply_to_each')?['email_html']
└─ Response 200
